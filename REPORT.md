## 2. Мета роботи

Пройти повний шлях від створення репозиторію до версії консольної програми, яку
відтворено збирають і запускають на Windows, macOS та Ubuntu.

Досягнуто:

- Maven-проєкт із Maven Wrapper, JUnit 5, SpotBugs і виконуваним jar;
- GitHub Actions перевіряє збірку на трьох ОС і публікує jar як артефакт;
- програма читає каталог книжок, відкидає хибні записи з поясненням,
  обчислює чотири показники та записує звіт у консоль і файл;
- робота спланована й здана через GitHub Issues та Pull Request.

## 3. Постановка задачі

Формат запису: `title:String; author:String; pages:int; price:double`.

Показники:

1. Кількість коректних записів.
2. Середня кількість сторінок.
3. Найдорожча книга.
4. Сумарна вартість каталогу.

Правила перевірки рядка (перша знайдена проблема стає причиною пропуску):

| Перевірка | Повідомлення |
|---|---|
| рядок порожній або з самих пробілів | `порожній рядок` |
| кількість полів не 4 | `очікується 4 поля, отримано N` |
| порожня назва або автор | `порожня назва книги`, `порожній автор` |
| порожнє числове поле | `порожня кількість сторінок`, `порожня ціна` |
| `pages` не відповідає `-?\d+` (`abc`, `240.5`, пробіли, `+5`) | `кількість сторінок не є цілим числом` |
| `pages` не вміщується в `int` | `кількість сторінок завелика` |
| `price` не відповідає `-?\d+(\.\d+)?` (`ціна`, `99,50`, пробіли, `10d`, `1e3`, `NaN`, `Infinity`) | `ціна не є числом` |
| `pages <= 0` | `кількість сторінок має бути додатною` |
| `price` з сотень цифр, що дає `Infinity` | `ціна має бути скінченним числом` |
| `price < 0` | `від'ємна ціна` |

Нульова ціна допустима (безкоштовна книга), нульова кількість сторінок – ні.

## 4. Структура програми

| Файл | Відповідальність |
|---|---|
| `Main.java` | розбір аргументів, керування обробкою, коди завершення |
| `BookParser.java` | розбір і перевірка одного рядка |
| `CatalogSummary.java` | накопичення чотирьох показників |
| `ReportFormatter.java` | формування тексту звіту з `Locale.ROOT` |
| `FileReport.java` | читання та запис файлів у UTF-8 через `Path` |
| `version.properties` | версія з `pom.xml` і номер CI-збірки для `--version` |

Потік даних:

```text
args → Main.run → FileReport.readLines → для кожного рядка BookParser.validate
     → коректний: CatalogSummary.add / хибний: «Рядок N: причина»
     → ReportFormatter.format → консоль + FileReport.writeReport
```

`main` лише викликає `run` і передає код завершення в `System.exit`. Завдяки
цьому `run` можна тестувати: `System.exit` у тесті зупинив би JVM разом із JUnit.

Читання, перевірка, обчислення та форматування розділені по класах, щоб у
лабораторній роботі № 2 замінити масиви рядків власними класами без зміни
зовнішньої поведінки.

## 5. Інфраструктура

- **Maven**: `pom.xml` з координатами `ua.lpnu.kzp:lab01:1.0.0`, Java 21, UTF-8.
- **Maven Wrapper** 3.3.4 (Maven 3.9.11): `mvnw`, `mvnw.cmd`, `.mvn/wrapper/`.
  У `.gitattributes` для `mvnw` задано LF, для `mvnw.cmd` – CRLF.
- **Залежності**: JUnit Jupiter 5.12.2 зі `scope test`.
- **Статичний аналіз**: SpotBugs 4.9.7.0, ціль `check` у фазі `verify`.
- **Пакування**: maven-shade-plugin 3.6.0, `Main-Class: ua.lpnu.kzp.Main`.
- **Версія**: `version.properties` заповнюється Maven (resource filtering) значеннями
  `${project.version}` і `${build.number}`.
- **CI** (`.github/workflows/ci.yml`): матриця `ubuntu-latest`, `windows-latest`,
  `macos-latest`; JDK 21 Temurin; кеш Maven; `clean verify` з
  `-Dbuild.number=${{ github.run_number }}`; запуск зібраного jar; публікація
  артефакта `lab01-<os>-build-<N>`.
- **Шаблони**: форми Issues `feature.yml`, `bug.yml` і `PULL_REQUEST_TEMPLATE.md`.

### Версія коду та номер CI-збірки

Версія `1.0.0` описує стан вихідного коду: вона однакова в `pom.xml`, Git-тезі
`v1.0.0` та виводі `--version` і змінюється лише тоді, коли змінюється продукт.
Номер збірки (`github.run_number`) – це порядковий номер запуску workflow: той
самий код можна зібрати багато разів (повторний запуск, інша гілка, PR), і кожна
збірка отримає новий номер. Номер збірки дає змогу знайти конкретний артефакт і
лог CI, а версія – зрозуміти, яку функціональність містить програма.

```text
$ java -jar lab01-1.0.0.jar --version
lab01 1.0.0 (build TODO: номер)
```

## 12. Висновки

Створено першу версію консольного продукту «Каталог книжок»: програма читає
записи з UTF-8 файла, відкидає хибні дані з номером рядка й причиною, обчислює
чотири показники та формує однаковий звіт у консоль і файл. Проєкт збирається
однією командою через Maven Wrapper, перевіряється тестами та SpotBugs і
автоматично збирається на Windows, macOS та Ubuntu з публікацією jar.

У лабораторній роботі № 2 масиви рядків (`String[]` з індексами
`BookParser.TITLE` тощо) буде замінено власним класом книги, а `BookParser`
повертатиме об'єкт замість масиву; класи `CatalogSummary`, `ReportFormatter` і
`FileReport` залишаться з тим самим призначенням.
