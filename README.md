# Каталог книжок

Консольна програма з курсу «Кросплатформні засоби програмування» (варіант 1).
Програма читає каталог книжок із CSV-файла, перевіряє кожен запис, обчислює
показники та формує звіт у консоль і текстовий файл.

Усі лабораторні роботи ведуться в цьому репозиторії; стан кожної здачі позначено тегом:

| Тег | Лабораторна робота | Що змінилося |
|---|---|---|
| `v1.0.0` | № 1 | консольна програма на рядках і масивах |
| `v2.0.0` | № 2 | клас-сутність `Book`, record `PagePrice`, валідація в конструкторі |
| `v3.0.0` | № 3 | ієрархія `Book` → `PrintedBook`, `ElectronicBook`, `enum BookFormat`, `equals`/`hashCode` |
| `v4.0.0` | № 4 | запити Stream API (`BookQueries`), показники через потоки, блок запитів у звіті |

## Показники

1. Кількість коректних записів.
2. Середня кількість сторінок.
3. Найдорожча книга.
4. Сумарна вартість каталогу.

## Формат входу

Файл у кодуванні UTF-8, один запис у рядку, поля розділено крапкою з комою.
Підтримуються два формати рядка:

```text
title;author;pages;price                              # формат ЛР № 1–2
title;author;pages;price;format;year;genre            # повний формат з ЛР № 3
```

| Поле | Тип | Обмеження |
|---|---|---|
| `title` | текст | не порожній |
| `author` | текст | не порожній |
| `pages` | ціле число | лише цифри, більше нуля |
| `price` | число з крапкою | лише цифри й необов'язкова дробова частина через крапку, не від'ємне |
| `format` | `PRINTED` або `ELECTRONIC` | точна назва, великими літерами |
| `year` | ціле число | від 1450 до поточного року |
| `genre` | текст | не порожній |

Рядок із 4 полями описує друковану книгу без року й жанру, тому файли
попередніх робіт обробляються без змін.

Приклади:

```text
Кобзар;Тарас Шевченко;320;250.00
Тигролови;Іван Багряний;288;99.00;ELECTRONIC;1944;роман
```

Пробіли навколо чисел, кома замість крапки, запис `10d`, `1e3`, `NaN` чи `Infinity`
вважаються помилкою. Рядки, які не проходять перевірку, пропускаються. У звіті для
кожного з них вказано номер рядка та причину.

Приклади даних:

- `data/input.csv` – формат ЛР № 1–2, контрольний файл для порівняння звітів;
- `data/books.csv` – повний формат: друковані й електронні книги та хибні рядки.

## Вимоги

- JDK 21 або новіший.
- Maven встановлювати не потрібно: його завантажує Maven Wrapper.

## Збірка

```text
./mvnw clean verify
```

У Windows замість `./mvnw` використовуйте `mvnw.cmd`. Команда `verify` компілює код,
запускає тести, збирає jar і виконує статичний аналіз SpotBugs.
Готовий файл: `target/book-catalog-4.0.0.jar`.

## Запуск

```text
java -jar target/book-catalog-4.0.0.jar [--help] [--version] [--input <файл>] [--output <файл>]
```

| Аргумент | Призначення | За замовчуванням |
|---|---|---|
| `--input <файл>` | вхідний CSV-файл | `data/input.csv` |
| `--output <файл>` | файл звіту | `out/report.txt` |
| `--help` | довідка | |
| `--version` | версія програми та номер CI-збірки | |

Шляхи за замовчуванням відносні, тому програму запускають з кореня проєкту.

Коди завершення: `0` – успіх, `1` – помилка роботи з файлом або немає жодного
коректного запису, `2` – неправильні аргументи.

## Модель даних

```text
          Book  (abstract sealed)
          ├── PrintedBook     вартість придбання = ціна + 50 грн доставки
          └── ElectronicBook  вартість придбання = ціна
BookFormat (enum): PRINTED «друкована», ELECTRONIC «електронна»
```

| Елемент | Призначення |
|---|---|
| конструктор `Book` | спільні інваріанти: назва й автор не порожні, `pages > 0`, ціна скінченна й `>= 0`, рік у межах, жанр не порожній |
| `Book.fromCsv(line)` | перевіряє структуру рядка й формат значень, обирає підтип за `format` |
| `purchaseCost()` | поліморфна операція: кожен підтип рахує вартість придбання по-своєму |
| `equals`/`hashCode` | книги рівні, якщо збігаються підтип, назва й автор |
| `Book.builder()` | будівник; `build()` викликає конструктор підтипу, тому перевірки не обходяться |
| `PagePrice`, `FormatTotals` | record для сум сторінок і цін та підсумків за форматом |

Об'єкти незмінні: поля `private final`, сеттерів немає. Код звіту обробляє всі книги
через тип `Book` і не перевіряє, друкована книга чи електронна.

## Запити

`BookQueries` виконує запити Stream API до списку коректних книг. Результати
виводяться в кінці звіту.

| Запит | Операції | Результат |
|---|---|---|
| книги від 2020 року | `filter` | `List<Book>` у порядку файла; книги без року не входять |
| назви | `map` | `List<String>` |
| кількість за жанром | `groupingBy` + `counting`, `TreeMap` | `Map<String, Long>`, жанри за абеткою |
| статистика сторінок | `summarizingInt` | `IntSummaryStatistics` |
| топ-5 за сторінками | `sorted` (сторінки ↓, потім назва ↑) + `limit` | `List<Book>` |
| пошук за назвою | `filter` + `findFirst` | `Optional<Book>` |
| жанри за форматом | `groupingBy` у `groupingBy` | `Map<BookFormat, Map<String, Long>>` |

Показники каталогу (`CatalogSummary`) теж обчислюються потоками: `reduce` для сум,
`max` для найдорожчої книги, `toMap` в `EnumMap` для підсумків за форматом.

## Структура

```text
src/main/java/ua/lpnu/kzp/
├── Main.java             аргументи командного рядка, керування обробкою
├── Book.java             базовий тип: інваріанти, fromCsv, equals/hashCode, будівник
├── PrintedBook.java      друкована книга: вартість із доставкою
├── ElectronicBook.java   електронна книга: вартість без доставки
├── BookFormat.java       enum формату видання
├── PagePrice.java        record «сторінки, ціна»
├── FormatTotals.java     record «кількість книг, вартість придбання» для формату
├── BookParser.java       розкладка полів CSV; перевірка рядка без створення об'єкта
├── CatalogSummary.java   незмінні показники каталогу, обчислені потоками
├── BookQueries.java      запити Stream API та пошук через Optional
├── ReportFormatter.java  формування тексту звіту
└── FileReport.java       читання та запис файлів у UTF-8
src/main/resources/version.properties   назва, версія та номер збірки для --version
src/test/java/ua/lpnu/kzp/              тести JUnit 5
src/test/resources/                     контрольні звіти v1.0.0 (input.csv) і v3.0.0 (books.csv)
data/input.csv                          приклад у форматі ЛР № 1–2
data/books.csv                          приклад у повному форматі
spotbugs-exclude.xml                    обґрунтовані виключення SpotBugs
docs/reports/                           звіти попередніх лабораторних робіт
```
